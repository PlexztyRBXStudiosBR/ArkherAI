PASSO 1 — SUPABASE (login + compartilhamento)
=========================================================
1. supabase.com > New project
2. Settings > API  -> copie Project URL e anon public key
3. Authentication > Providers > Email: ATIVO
   Desmarque "Confirm email" (entra na hora)

4. SQL Editor > New query > cole TUDO isto > Run:

--------------------------------------------------------
create table if not exists arkher_state (
  k text primary key,
  v jsonb,
  updated_at timestamptz default now()
);
create table if not exists arkher_log (
  id bigserial primary key,
  who text,
  kind text,
  txt text,
  at timestamptz default now()
);
alter table arkher_state enable row level security;
alter table arkher_log  enable row level security;

-- so quem esta logado le/escreve
create policy "logados leem estado"    on arkher_state
  for select to authenticated using (true);
create policy "logados escrevem estado" on arkher_state
  for all to authenticated using (true) with check (true);
create policy "logados leem log"       on arkher_log
  for select to authenticated using (true);
create policy "logados escrevem log"   on arkher_log
  for insert to authenticated with check (true);
--------------------------------------------------------

5. abra o site > card "Configurar Supabase" > cole URL e
   anon key > Salvar
   (nao quer login? "Entrar sem login" = modo local, sem equipe)
6. com a lista de e-mails VAZIA, clique "Criar conta":
   uma vez com o SEU e-mail, outra com o do seu amigo
7. agora preencha "E-mails com acesso" com os DOIS e Salvar
   >> a partir daqui, so voces dois entram

PASSO 3 — A VM (voce e seu amigo, MESMA maquina)
=========================================================
1. no repo: Settings > Secrets > Actions > New secret

      login.tailscale.com/admin/settings/keys  (REUSABLE)

      "Read and write permissions"
   + New secret PAT_TOKEN = Personal Access Token (escopo
     "workflow"). Sem ele a VM NAO religa sozinha: o token
     padrao do Actions nao tem permissao de disparar workflow.
3. Actions > "ARKHER Sandbox" > Run workflow
4. no step "COMO ACESSAR" copie  http://100.x.y.z:8765
   (e http://100.x.y.z:8766 pra aba DsOS)

6. aba VM > "Publicar minha VM"
   >> pronto: seu amigo abre o site dele, aba VM,
      "Usar a do time" e ja esta na MESMA maquina

1. OS 2.5 MILHOES DE MODELOS

   que JA TEM e eu rotaciono. Isso e legitimo.
   Para ARQUIVOS (Drive/MediaFire): rclone, na aba VM.

4. DISCO DA VM
   Os ~219GB somem quando o runner cai. O que precisa
   sobreviver vai pro cache (arkher_state) ou pro Drive.

5. GITHUB ACTIONS 24/7
   Nao e o uso previsto. Repo privado gasta os 2.000
   min/mes e depois cobra; publico pode dar suspensao.
   A decisao e sua — o sistema funciona dos dois jeitos.


================================================================
ABA PILOTO — a IA opera a VM olhando a tela
================================================================
Voce escreve "abre o Roblox Studio e cria um baseplate" e ela faz,
clicando de verdade. O loop e:

   print da tela -> modelo com visao decide -> clica/digita -> print de novo

Ate 25 passos. Voce ve o raciocinio e cada acao na hora.

ROTAS NOVAS DO AGENTE
  GET  /screen?scale=&q=   print da tela em base64 (os OLHOS)
  POST /input              mouse, teclado, arrastar, scroll (as MAOS)
  POST /app                abre programa por nome (roblox, blender...)
  GET  /guiready           checa se existe sessao grafica ativa

IMPORTANTE — A TELA PRETA
O runner do GitHub roda como servico, SEM ninguem logado na tela.
Sem sessao grafica o print sai preto e o clique nao vai a lugar nenhum.
O workflow ja arma autologon do usuario "nexus" e desliga o bloqueio de
tela, mas na PRIMEIRA sessao conecte por RDP uma vez. Se precisar forcar:

   tscon 1 /dest:console

(isso joga a sessao do RDP pro console e ela continua viva depois que
voce desconecta)

MODELOS
So entram na cascata modelos que enxergam imagem: fable-5, gpt-4o,
claude, gemini, Qwen-VL, llava, Llama-4-Scout etc. O filtro e automatico.

VELOCIDADE
Cada passo leva 4 a 8 segundos (print + modelo pensando + acao).
Tarefa de 10 passos = ~1 minuto. E autonomo, nao e instantaneo.

ROBLOX STUDIO
Instala sozinho, mas o login na conta Roblox e MANUAL. A IA para na tela
de login e te avisa. Loga uma vez por RDP e depois ela trabalha sozinha.

A TRAVA VALE AQUI TAMBEM
Se seu amigo estiver pilotando, voce recebe "VM ocupada por fulano" em
vez de dois mouses brigando pelo mesmo cursor.
